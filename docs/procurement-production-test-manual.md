# 加盟商直采 · 正式环境测试操作手册

> 适用分支:`codex/merge-batch12-into-procurement`(或其合入 `main` 后的版本)。
> 上线该分支前先在本机跑 `npm run codex:preflight:full`(含直采专属冒烟 `procurement-smoke`)。
> 核心安全设计:功能有三重开关,**默认全关**,不打开对现网零影响;所有资金/库存变动走 append-only 账本,可随时对账。

---

## 0. 四个角色与入口

| 角色 | 登录身份 | 入口页面 | 测试中负责 |
| --- | --- | --- | --- |
| 总部运营 | pontomall/pontosys 办公账号 | 商城工作台 `/mall` → **直采 Tab** | 开关、商品采购配置、审批、确认收款、对账 |
| 供应商 | supplier 门户账号 | `/mall/supplier` | 开放直采同意、接单、发货、确认对账单 |
| 加盟商 | franchise 门户账号 | `/mall/franchise`(选货→订货→跟单) | 充值押金、下采购单、跟单 |
| 站点 | 站点账号 | `/mall/station`(兑换到货/收货入库/本站库存) | 收货入库、清点差异、兑换出库 |

**正式环境测试原则**:专门建 1 个测试加盟商 + 1 个测试供应商 + 1 个测试商品(供货价 R$1–5 的小金额),全程不碰真实商户数据;测完保留账本记录(append-only 本来也删不掉),把测试单走到终态即可。

## 1. 开关说明(总部 · 直采 Tab 顶部)

| 开关/参数 | 含义 | 测试建议值 |
| --- | --- | --- |
| `procurementEnabled` | 总开关,只控制**新下单**,在途单不受影响 | 测试时开,平时关 |
| `procurementFrozen` | 🚨 紧急冻结,阻断一切直采写操作(423) | 出问题立刻开它,不用回滚代码 |
| `stationStockEnforcement` | M3:骑手兑换改为消耗站点库存(替代中央库存扣减) | 第 6 步前再开,先跑通采购链 |
| 自动审批阈值 (BRL) | 低于此金额的采购单免总部人工审批 | 测试期设 0(全部人工审) |
| 单笔上限 (BRL) | 单张采购单金额上限 | 设 50,防手滑 |
| 发货超时天数 | 供应商超时未发货的提醒 | 默认即可 |

## 2. 测试前置(一次性)

1. 部署分支到正式环境,确认 `/api/mall/procurement` 可访问(GET 返回 401/数据而非 404)。
2. 总部 → 直采 Tab:开 `procurementEnabled`,设单笔上限 R$50、自动审批 0。
3. 建测试账号:供应商团队账号(供应商门户「团队账户」Tab 可自建)、测试加盟商账号、测试站点账号。
4. 测试商品:供应商门户上传(供货价设 R$2,周期 1 天)→ 总部定价上架。

## 3. 链路一:供应商同意 + 商品可采配置

1. **供应商** `/mall/supplier` → 商品 Tab → 测试商品卡「开放直采」区:打开开关,填建议价 → 状态变「待总部审批」。
2. **总部** `/mall` 直采 Tab → 同意审批队列:批准该商品。
3. **总部** 商品采购配置:设采购模式(先选 `consignment` 代销)、加盟商买断价、起订/限订量。
4. **验证点**:审批前加盟商目录看不到该商品;批准后 `/mall/franchise` 选货目录出现。
   反向验证:供应商改一次分销设置 → 审批状态应自动重置为待审批。

## 4. 链路二:押金充值(买断链路的前置)

1. **加盟商** `/mall/franchise` → 押金余额区 → 申请充值(R$30,填 PIX 凭证号)。
2. **总部** 直采 Tab → 充值确认:确认到账 → 加盟商押金余额 +30。
3. **验证点**:押金账本出现一条 `topup` 分录,余额快照正确;重复点确认不会重复入账(幂等)。

## 5. 链路三:代销采购全链(不占资金)

1. **加盟商**:选货 → 测试商品(代销)→ 选站点、数量 5 → 下单。因自动审批=0,单进「待总部审批」。
2. **总部**:直采 Tab 审批通过 → 单到供应商。
3. **供应商** `/mall/supplier` 物流 Tab:确认接单 → 标记发货(填物流单号)。
4. **站点** `/mall/station` 收货入库 Tab:实收 4 件、短装 1 件提交。
5. **验证点**:站点库存代销池 +4;自动生成 1 条差异单(short),总部直采 Tab 可见并处理;供应商应付将按**实收数**计。

## 6. 链路四:买断采购 + 退款路径

1. **加盟商**:下买断单(数量 2,货款从押金即时扣除)→ 押金余额减少,押金账本出现 `order_debit` 分录。
2. 走完 审批→接单→发货→收货,这次实收 1 件短装 1 件。
3. **验证点**:短装自动按快照单价退款回押金(账本 `refund` 分录);毛利账本出现买断价差分录及对应的**负数冲销分录**(短装部分)。
4. 再下一张买断单然后**加盟商撤单**:验证全额退款分录 + 毛利全额冲销。

## 7. 链路五:M3 兑换消耗站点库存

1. 总部开 `stationStockEnforcement`。
2. 用测试骑手在商城兑换该商品(取货站点=测试站点)。
3. 站点确认取货(核销)。
4. **验证点**:站点库存代销池 −1(reserve→outbound);中央 `product.stock` 不再扣减;毛利账本出现一条 `consignment_spread` 分录;供应商应付新增该单。

## 8. 链路六:对账与毛利

1. 月初(或手动)生成供应商对账单:确认买断单按快照价 × 实收数入账、代销按兑换出库入账、**纯买断池出库的兑换单不重复计入**(防双付)。
2. **供应商**确认对账单(填 PIX)→ **总部**标记付款。
3. **验证点**:付款后对应毛利账本分录从 `accrued` 翻 `settled`;直采 Tab 毛利表按月合计 = 买断价差 + 代销价差 − 冲销。
4. 争议演练:供应商对某张账单点「有异议」→ 总部「重新打开」→ 重新生成。

## 9. 验收核对清单(全部通过才算功能可开放)

- [ ] flag 关闭时,加盟商端整个直采区块不可见,API 下单 403
- [ ] `procurementFrozen` 打开时所有直采写操作被 423 拦截
- [ ] 押金余额 = 押金账本重放结果(充值−扣款+退款)
- [ ] 站点库存 = 站点库存账本重放结果;代销/买断池分开
- [ ] 每笔买断扣款都有毛利分录;每笔退款都有对应冲销分录
- [ ] 供应商对账单无双付(买断池出库的兑换单被排除)
- [ ] 供应商未同意(或修改后待审)的商品无法被下单/加入目录
- [ ] 审计日志覆盖:下单/审批/收款/收货/差异/对账/争议各环节

## 10. 出问题怎么办

| 情况 | 动作 |
| --- | --- |
| 发现资金/库存计算异常 | 立刻开 `procurementFrozen`(在途单冻结,数据保留),排查账本分录定位 |
| 只想停新增、让在途单走完 | 关 `procurementEnabled` |
| 测试数据要收尾 | 把测试单全部走到终态(收货/取消),不要留 in-flight;账本记录保留即可 |
| 需要彻底下线 | 两个 flag 全关 → 功能对所有端隐藏,代码可留在线上 |
