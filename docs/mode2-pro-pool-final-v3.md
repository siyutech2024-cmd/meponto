## 二、闭环验证（五条主流程逐一走通）

### 环 1 · 骑手生命周期 ✅

```
99 名单 → 批量标记入池（审计）→ App 看到 PRO 排班表 → 被加盟商填入班表
→ 锁定上报 → 99 排班时段内接单 → T+1 单量回流 → 积分入账 → 周考核
→（达标）留池 ／（违规）移出 → 次日 0 点回普通池，App 自动切回普通表
```

闭环成立。**补一条规则**：出池生效次日 0 点，当日已锁定名册照常执行完毕（避免当天名册与 99 侧冲突）。

### 环 2 · 订单与钱 ✅

```
99 新 OL 日报 → 导入（单量，零金额）
  ├─ 对账 A：我方单量 vs 99 结算单（T+1 差异表）——单量即金额乘数
  ├─ 对账 B：总部↔加盟商 PRO 小计 = 单量 × 12（两端视图一致）→ 月结支付 → 支付确认留痕
  └─ 骑手：App 见单量 → 与加盟商线下核对工资
```

闭环成立，但有**一个有意识接受的开环**：骑手工资在系统外，我们看不见拖欠。对冲三件套（App 单量凭证提示 / "PRO 工资纠纷"工单分类 / 投诉率进加盟商考核）+ 若纠纷多发二期恢复计酬引擎（表结构已预留）。

### 环 3 · 排班→接单权→监控 ✅

```
总部分两套名额 → 加盟商填 PRO 表（池校验）→ 总部审核 → 傍晚锁定
→ 名册上报 99（状态条可见/失败告警/留档）→ 99 按名册放行接单
→ 实时抓取 → 应岗未上红色 → 催报/升级（审计）→ 周考核取数
```

闭环成立。**新的单点风险 = 名册同步链路**，三重兜底：上报状态条（发现）+ 手动 runbook（人肉补报）+ 回退时 99 侧解除管控的操作路径（待 99 提供，已列确认项）。

### 环 4 · 积分与激励 ✅

完单事件双源合流后，完单积分→商城兑换、邀请首单触发、Partner 扫码验证、会员等级四条链路全部自动正确，无单独改动。上线周各验一例。闭环成立。

### 环 5 · 数据与汇报 ✅

双源导入（缺源告警）→ KPI 分池（P1 tab）→ 周报表（P1）→ 例会两张表（模式一/旧池报单均；PRO 池报单量/TSH/在岗率）。**口径纪律：对外汇报一律以导入报表为准，抓取数据仅用于实时监控。** 闭环成立。
