## 1. 核心发现:排行榜不需要发 APP

### 依据

1. 服务端认证走 `meponto_session` **cookie**(`lib/auth-session.ts`)
2. A5 的 WebView **已经注入这个 cookie**,域写死 `.meponto.com`(v2.6 已实现)
3. A5 白名单允许 `*.meponto.com` 在 APP 内打开

所以:把排行榜做成 `mall.meponto.com/rider-app/ranking` 这张 H5 页,用 A4 活动卡
指过去,**在 APP 内打开即是登录态,不用再登录一次**,"我的名次"能正确识别到人
—— 全程不用改一行 Kotlin。

### ✅ 登录链路已验证(2026-08-07)

| 环节 | 事实 |
|---|---|
| APP 的 API 地址 | `https://mall.meponto.com/api/`(build.gradle BASE_URL) |
| 会话 cookie 存在哪 | OkHttp jar,host = `mall.meponto.com` |
| injectSession 读哪个域 | `https://mall.meponto.com/` ← **对得上** |
| 写进 WebView 时的 Domain | `.meponto.com` ← 覆盖主域和所有子域 |
| SameSite=Lax 会不会拦 | 不会。顶层导航允许带 cookie,页面内又是同源 fetch |

### ⚠️ 正确的 linkURL 是 `app.meponto.com/ranking`(2026-08-07 实测更正)

之前根据 build.gradle 的 BASE_URL 推断"必须填 mall.meponto.com" —— **这条是错的**,
实测打开 `mall.meponto.com/rider-app/ranking` 被弹到了 `app.meponto.com/register`。

真实的域路由在 `proxy.ts`:

| 规则 | 效果 |
|---|---|
| `mall.meponto.com` 上的 `/rider-app/*` | 302 到 `app.meponto.com/<去掉前缀的路径>` |
| `app.meponto.com` 上的 `riderSections` 白名单 | rewrite 到 `/rider-app/<page>` |
| 不在白名单的路径 | 掉进"严格域⇄门户绑定" → 弹回 `/` → 未登录再跳 `/register` |

`ranking` 当时**不在 riderSections 里**,所以两个域都打不开 —— 页面代码没问题,
是路由没登记。已加入白名单。

    正确 → https://app.meponto.com/ranking
    (mall.meponto.com/rider-app/ranking 也能到,但白白多一跳)

cookie 域是 `.meponto.com`,两个子域都带得上,登录态不受影响。

> **给以后:新增任何骑手页面,必须同时把它的一级路径加进 `proxy.ts` 的
> `riderSections`。** 漏了的表现是"页面打不开、跳去注册页",极难联想到路由。

### ⚠️ 硬约束(不满足就退化成"未登录"页)

**这张页面绝不能依赖 `localStorage`。**

现有 `/rider-app/*` 页面用 `readSession()` 读 localStorage 来判断"有没有登录"。
但 WebView 的 localStorage 和 APP 自己的存储是两套,**注入的只有 cookie**。
所以 ranking 页必须:

- 不调用 `readSession()`,不做任何客户端登录判断
- 直接 `fetch('/api/rider/leaderboard')`,浏览器自动带上 cookie
- 由服务端响应告诉页面"你是谁、你第几名";响应里没有 `me` 就是没登录

这条写死在代码注释里,否则以后有人照着别的 rider-app 页面抄一遍 `readSession()`,
页面就会在 APP 里显示"请先登录"。

### 前置依赖

**v2.6 必须先上架。** 活动卡(A4)和 WebView(A5)都在 v2.6 里。
v2.4 用户没有活动卡,自然也看不到入口 —— 不会报错,只是看不见。

## 2. 活动体系全景

```
主后台 APP 配置页
  ├── 开屏(splash)          → 引流,可定向"仅 PRO"
  ├── 活动入口卡(A4)        → 首页 banner,可定向 + 起止日期
  │     └── linkURL ────────┐
  └── 排行榜开关            │
        enabled/daily/weekly│
        topN                │
                            ▼
                   A5 WebView(白名单 *.meponto.com,注入 cookie)
                            │
                            ▼
              meponto.com/rider-app/ranking(H5)
                            │
                            ▼
                  GET /api/rider/leaderboard
                            │
                            ▼
                   rider_status_snapshots
                   (每人每天 MAX,不是 SUM)
```

**一句话:活动卡是入口,H5 是内容,排行榜是第一个内容。**
以后要做别的活动页(抽奖、任务、榜单季),同一条路径复用,都不用发版。

## 3. 排行榜口径(已定 + 待决)

### 已定(业务方 2026-08-06)

| 项 | 结论 |
|---|---|
| 分池 | 一张总榜,PRO 与普通混排,PRO 标金色 |
| 姓名 | 显示全名 |
| 数据源 | 实时抓取快照 |

### 实现要点

- `finished_cnt` 是**当日累计**,不是增量 → 每人每天取 `MAX`
- 周榜 = 若干天各自 MAX 再相加
- 快照保留 48 天(实测 5,936 批次 / 33.6 万行),够算
- 榜单截到 topN,但**本人名次永远附带**,哪怕排在榜外

### ⚠️ 待你决定的三件事

#### D1. 周榜的"周"怎么算 ✅ 已定(2026-08-07)

**自然周,周一到周日。** 下一个完整周从 2026-08-10(周一)开始。

已实现:`weekWindow()` 从 `api/assessment` 提到 `lib/assessment`,
排行榜和考核页**共用同一个函数** —— 各写一份迟早会漂移。
周一零点自动清零;界面上显示完整周期(周一–周日),骑手知道还有几天可以追。

#### D2. PRO 霸榜怎么办 ⏸ 已定:不加(2026-08-07)

业务方决定不加"本站点榜"。以下分析保留备查,如果日后普通骑手反馈"榜单跟我没关系",
这就是现成的解法。



PRO 是全职,单量天然高。一张总榜跑起来后,前 20 名很可能全是 PRO,
普通骑手看一眼发现自己永远进不去,激励作用对**大多数人**失效。

现在已有的缓解:本人名次永远显示(至少知道自己第几)。

如果实际数据证实霸榜,可选加一个"范围"切换:全部 / 本站点。
本站点榜里普通骑手互相比,竞争才有意义。**建议先上线观察一周再决定**,
不要提前加复杂度。

#### D3. 隐私口径 ⏸ 已定:不考虑(2026-08-07)

业务方决定按全名上线。以下提示保留备查。



显示全名 + 单量 = 把每个骑手的产能对全体同事公开。
巴西 LGPD 下,员工/合作方之间公开个人绩效数据是有争议的地带。

我不是律师,不能给法律结论。但这件事值得在 N4(加盟商告知书)那一轮
一并让法务看一眼 —— 尤其"显示全名"是可以随时改成脱敏的,上线后再改反而尴尬。

## 5. 与"进出池规则"(R10)的关系

排行榜和进出池是**两件事,别混**:

- 排行榜 = 激励,用**实时抓取**,谁都能看,错一点无所谓
- 进出池 = 处罚/晋升,用**T+1 导入**,影响一个人的收入,必须准

代码上也要分开:排行榜读 `rider_status_snapshots`,进出池读 `riderDailyKpis`。
**绝不能因为榜单排名低就自动出池** —— 抓取数据漏一个批次就会冤枉人。
